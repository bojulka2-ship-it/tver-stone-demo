# Лендинг завода «ТверьКамень»

## 1. Назначение

Одностраничный корпоративный сайт завода по производству тротуарной плитки. Задача: показать преимущества завода и собрать заявки клиентов.

- Клиент **звонит** по номеру завода или **оставляет заявку** через форму.
- Заявка уходит **на почту менеджеров завода** одним аккуратным HTML-письмом (имя, телефон, способ связи, контакт, время).
- Способ, которым менеджер связывается с клиентом, **выбирает клиент** в форме: перезвонить / WhatsApp / Telegram / e-mail.

Стек: статический HTML/CSS/JS. Сейчас проект опубликован как **публичное демо на GitHub Pages** (без бэкенда, форма имитирует приём с пометкой «демо»). боевой режим с реальной отправкой заявок включается на **домене в России** после покупки решения заказчиком — см. раздел 9.

Обработчик формы — два взаимозаменяемых варианта (выбор одной строкой в `js/config.js`, `API_URL`):
- **PHP-хостинг в РФ** (основной вариант для запуска): `send.php`, адрес `/send.php`; письмо через `mail()`/SMTP хостинга, данные — только на территории РФ (152-ФЗ);
- **Node-бэкенд** (опционально): `netlify/functions/submit.mjs` или аналогичная функция любого Node-хостинга, адрес `/api/submit`.

Дополнительно есть **демо-режим** без бэкенда — **GitHub Pages**: на поддоменах `*.github.io` `js/config.js` автоматически выставляет `IS_GITHUB_PAGES = true`, форма имитирует приём заявки локально (с явной пометкой «демо» и ссылкой на пример `zayavka.html`), ничего не отправляя.

Персональные данные обрабатываются на территории России, трансграничная передача не осуществляется. Для заявки обязательно получается согласие на обработку ПДн (чекбокс + ссылка на `policy.html`) — 152-ФЗ.

## 2. Интерфейс и функциональность

Секции страницы (сверху вниз): шапка (логотип + телефон · контакты завода — **только телефон**, без мессенджеров) → hero (преимущества, CTA «Рассчитать стоимость») → проблемы и решения → калькулятор площади → форма заявки → преимущества/гарантии → отзывы → контакты (адрес, режим работы, телефон) → футер (телефон, в демо — ссылка «Пример заявки менеджеру») → мобильная панель «Позвонить / Рассчитать стоимость».

Форма заявки:
- Имя + телефон (маска `+7 (…) …-…-…`, ровно 11 цифр).
- Выбор способа связи менеджера: перезвонить / WhatsApp / Telegram / e-mail (условные поля: мессенджер → `@username`, почта → e-mail).
- После отправки: «Ваша заявка принята. Наши менеджеры свяжутся с вами…» (в демо — с пометкой «демо» и ссылкой на пример письма).
- Антиспам: скрытое поле-ловушка и ограничение частоты заявок с одного IP.
- Калькулятор: площадь м² × 800 ₽/м² (базовая цена, уточняется менеджером).

Страница-пример `zayavka.html` — как выглядит заявка у менеджера (письмо со всеми полями); в демо доступна из футера и из сообщения об успехе формы.

## 3. Демо на GitHub Pages: как открыть и что проверить

**Адрес демо:** https://bojulka2-ship-it.github.io/tver-stone-demo/

Открывается в любом браузере без скачивания и логина, работает из РФ (HTTP/2 и HTTP/1.1). Ничего устанавливать не нужно.

### Как работать в демо (показ менеджеру/заказчику)

1. Откройте ссылку выше.
2. Пролистайте страницу: все секции, картинки, шрифты, отзывы, контакты.
3. В калькуляторе двигайте ползунок площади — сумма пересчитывается (площадь × 800 ₽).
4. В форме: введите имя, телефон (маска подставит формат), выберите способ связи — при WhatsApp/Telegram/почте появляется условное поле.
5. Отметьте чекбокс согласия (без него отправка блокируется — проверьте: появляется сообщение).
6. Нажмите «Рассчитать стоимость» — через ~1 секунду зелёное сообщение: **«Ваша заявка принята (демо-режим…)»** + ссылка **«Посмотреть, как выглядит заявка у менеджера →»**.
7. Откройте эту ссылку (или футер «Пример заявки менеджеру») — страница `zayavka.html` с примером письма менеджеру.
8. Проверьте `policy.html` (ссылка из чекбокса) — политика 152-ФЗ открывается.
9. Мобильная проверка (по желанию): узкое окно/телефон — адаптив, нижняя панель «Позвонить / Рассчитать стоимость», кнопка «Позвонить» набирает номер.

### Что должно быть видно (чек-лист демо)

- ✓ Страница открывается без VPN и без ошибок.
- ✓ Все секции и изображения загружаются, шрифты локальные.
- ✓ Калькулятор пересчитывает сумму.
- ✓ Маска телефона работает, формат `+7 (999) 123-45-67`.
- ✓ Условные поля появляются/скрываются при смене способа связи.
- ✓ Без согласия форма не отправляется (ошибка под формой).
- ✓ С согласием — зелёное сообщение с явной пометкой **«демо-режим»** (это нормально: заявки не сохраняются).
- ✓ Из сообщения/футера открывается `zayavka.html` с примером заявки.
- ✓ `policy.html` открывается, есть чекбокс согласия.
- ✗ Заявка в демо **не приходит** ни на почту, ни в логи — это ожидаемо (нет сервера).

Важно: демо показывает **интерфейс и сценарий**, но не приём заявок. Реальный приём включается при запуске на домене (раздел 9).

## 4. Системные требования

**Демо (GitHub Pages, текущий режим):**
- Публичный репозиторий на GitHub с папкой статики `site/` в корне ветки `main`; Pages включён: Settings → Pages → Source **«Deploy from a branch»** → `main` / `(root)`.
- Бэкенд не нужен: `IS_GITHUB_PAGES` переводит форму в имитационный режим. Заявки не сохраняются.

**Запуск на домене в РФ (боевой режим):**
- Хостинг в России с **PHP 8.0+** (проверено на 8.4) и включённой функцией `mail()` (или SMTP хостинга) — для `send.php`.
- Веб-сервер **Apache** (`.htaccess`) или **nginx** (запрет доступа к `logs/` и `config/` — см. раздел 9).
- Права записи на папку `logs/` (журнал режима `test` и rate-limit).
- Альтернатива: Node-бэкенд (`/api/submit`) — при выборе Node-хостинга.

**Для локальной разработки:** PHP CLI (для PHP-тестов); Node.js ≥ 18 (для тестов функции и сборки `site/`).

## 5. Установка и локальный запуск

Локально (PHP-режим, проверка формы «в лог»):

```
php -S 127.0.0.1:8080
```

Откройте http://127.0.0.1:8080 — при `mode: test` заявка пишется в `logs/mail.log`.

Для боевого запуска (после покупки решения заказчиком):
1. Скопируйте проект на хостинг (в document root сайта).
2. Заполните `config/managers.local.php`: адреса менеджеров, `mode => 'real'` (раздел 8.2).
3. В `js/config.js` убедитесь, что `API_URL = "/send.php"`.
4. Замените телефон-заглушку `+7 (900) 000-00-00` на реальный номер (4 места в `index.html`).
5. Создайте папку `logs/` с правами на запись (`chmod 775`).

> На Windows `mail()` не работает — локально используйте только `mode => 'test'`.

## 7. Проверка (тесты и сценарии)

Автотесты (валидация, согласие, honeypot, rate-limit, ошибки формы):

```
node tests/api.test.mjs      # Node-бэкенд  → 6/6 PASS
php tests/run_tests.php      # PHP-бэкенд   → 7/7 PASS (нужен php в PATH)
npm test                     # оба набора последовательно
npm run build:netlify        # собрать site/
```

Дополнительно: `node --check js/script.js js/config.js netlify/functions/submit.mjs` (синтаксис).

Смоук-проверка в браузере: заполнить форму (отметить согласие) валидными данными → «заявка принята». В PHP-режиме `test` — запись в `logs/mail.log`; в `real` — письмо на почту менеджера. В демо (GitHub Pages) — сообщение с пометкой «демо» + ссылка на `zayavka.html`. Полный сценарий приёмки — в `ACCEPTANCE_CHECKLIST.md`; чек-лист демо — в разделе 3.

## 8. Конфигурация

### 8.1. PHP-режим (основной для запуска в РФ)

Конфигурационный файл, без OS-переменных:

| Имя (ключ) | Где задаётся | Формат / пример | По умолчанию | Назначение |
|------------|--------------|-----------------|--------------|------------|
| `managers` | `config/managers.php` или `managers.local.php` | массив e-mail: `['sales@example.ru']` | `['manager@example.ru']` | Получатели заявок |
| `from` | там же | e-mail отправителя | `noreply@<домен>` | Обратный адрес письма |
| `mode` | там же | `'test'` / `'real'` | `'real'` (fail-closed) | `test` — только журнал; `real` — отправка письма |
| `debugLogFile` | там же | абсолютный путь | `logs/mail.log` | Файл журнала в режиме `test` |
| `rateLimitWindowSeconds` | там же | число сек. (0 = выкл.) | `60` | Окно частоты заявок |
| `rateLimitMax` | там же | число заявок (0 = выкл.) | `5` | Лимит заявок за окно с одного IP |

Секретные/реальные значения (адреса менеджеров) задавайте в `config/managers.local.php` — он не попадает в git. Шаблон `config/managers.php` в поставке содержит только плейсхолдеры. В коде и в git никаких реальных адресов и паролей нет.

### 8.2. Node-бэкенд (опционально)

Если выбран `/api/submit`, переменные окружения хостинга:

| Имя переменной | Формат / пример | По умолчанию | Назначение |
|----------------|-----------------|--------------|------------|
| `NETLIFY_SUBMIT_MODE` | `test` / `real` | `test` | `test` — заявка логируется, письмо не шлётся; `real` — отправка на SMTP |
| `MAIL_TO` | JSON-массив или список | — | Получатели заявок (менеджеры) |
| `MAIL_FROM` | e-mail | пусто (`SMTP_USER`) | Обратный адрес письма |
| `SMTP_HOST` | `smtp.mail.ru` / `smtp.yandex.ru` и т.п. | — | SMTP-сервер (российский) |
| `SMTP_PORT` | `465` / `587` | `465` | Порт SMTP |
| `SMTP_SECURE` | `true` / `false` | `true` | TLS (для 465 — true) |
| `SMTP_USER` | e-mail ящика | — | Логин SMTP |
| `SMTP_PASS` | пароль приложения | — | Пароль SMTP (НИКОГДА не в git) |
| `SUBJECT_PREFIX` | `[ТверьКамень] ` | `[ТверьКамень] ` | Префикс темы письма |
| `RATE_LIMIT_WINDOW_SECONDS` | число сек. (0 = выкл.) | `60` | Окно частоты заявок |
| `RATE_LIMIT_MAX` | число заявок | `5` | Лимит заявок за окно с одного IP |

## 9. Запуск на реальном домене в России (после покупки решения заказчиком)

Когда заказчик принял решение и купил домен/хостинг, проект переводится из демо в боевой режим. Последовательность:

### Шаг 1 — Домен и хостинг (покупка заказчиком)
1. Домен у российского регистратора (reg.ru, RU-CENTER и т.п.) — например, `tver-kamen.ru`.
2. Хостинг в России с PHP 8+ (любой российский хостинг-провайдер). Данные заявок и письма не покидают РФ — требование 152-ФЗ.
3. Бесплатный SSL-сертификат (Let’s Encrypt выдаёт большинство хостингов в один клик) — сайт открывается по `https://`.

### Шаг 2 — Загрузка проекта
1. Загрузите файлы проекта в document root хостинга (FTP/панель управления/file-manager).
2. `logs/` — создайте локально с правами записи (775); `config/` и `logs/` защищены `.htaccess` (Apache) — для nginx добавьте `location ^~ /logs/ { deny all; }` и `location ^~ /config/ { deny all; }`.
3. Права: файлы `644`, папки `755`, `logs/` — `775`.

### Шаг 3 — Конфигурация (один раз)
1. `config/managers.local.php`: реальные адреса менеджеров, `mode => 'real'`.
2. `js/config.js`: `API_URL = "/send.php"` (уже так по умолчанию для PHP-варианта).
3. Телефон: заменить `+7 (900) 000-00-00` на реальный номер в `index.html` (4 места).
4. `policy.html`, раздел 1: вписать реальные реквизиты оператора (наименование, ИНН/ОГРН, адрес).
5. При необходимости поправить тексты/цены/адрес в `index.html`.

### Шаг 4 — Проверка боевого режима
1. `/logs/mail.log` и `/config/managers.php` извне → 403/404 (защита работает).
2. Отправить тестовую заявку с сайта → письмо пришло менеджеру (или запись в `logs/mail.log` при `mode=test`).
3. Пройти `ACCEPTANCE_CHECKLIST.md` целиком.
4. Если письма в «Спаме» — настроить SPF/DKIM/DMARC для домена отправителя.

### Шаг 5 — Передача
1. Доступ к домену/хостингу и репозиторию — заказчику.
2. Форма работает на `https://<домен>/`, заявки приходят на почту менеджеров.
3. Демо на GitHub Pages можно оставить как «витрину» или снять с публикации.

Пример SMTP для PHP-хостинга (если хостинг требует PHPMailer, например Яндекс.Почта):

```php
$mail->isSMTP();
$mail->Host = 'smtp.yandex.ru';
$mail->Port = 465;
$mail->SMTPSecure = 'ssl';
$mail->Username = 'login@yandex.ru';
$mail->Password = 'пароль приложения'; // пароль — в конфиге, не в коде
```

## 10. Деплой и обновление демо (GitHub Pages)

**Текущая публикация:** репозиторий `bojulka2-ship-it/tver-stone-demo` (публичный), Pages: Source **«Deploy from a branch»** → `main` / `(root)`.

Как обновить демо:
1. Пересоберите статику: `npm run build:netlify` → папка `site/`.
2. Скопируйте содержимое `site/` в корень репозитория демо (вместо старых файлов).
3. `git add -A && git commit -m "..." && git push`.
4. GitHub Pages пересоберёт сайт автоматически (~1–2 минуты), проверьте URL.

Исходный код проекта хранится в основном репозитории; демо-репозиторий содержит только собранную статику `site/`.

Для показа заказчику достаточно дать ссылку на демо (раздел 3) — ничего скачивать не нужно.

## 11. Резервное копирование

- Что бэкапить: `config/managers.local.php` (реальные адреса), `logs/` (журнал заявок), изменённые изображения/тексты.
- Что НЕ бэкапить (генерируется заново): `site/` и всё остальное — проект восстанавливается из git (история коммитов).
- Рекомендуемая частота: после каждого изменения конфигурации или перед обновлением.

## 12. Ограничения

- Осталась телефон-заглушка `+7 (900) 000-00-00` — реальный номер вносится при запуске (единственный внешний блокер приёмки).
- Реквизиты оператора в `policy.html` (раздел 1) вписываются заказчиком при запуске.
- **Демо (GitHub Pages) заявки не сохраняет** — нет серверного обработчика; форма помечает приём как «демо» и показывает пример `zayavka.html`. Это витрина для показа, не приёмка формы.
- `mail()` не работает на Windows — PHP-режим `real` проверяется только на Linux-хостинге; локально — `test`.
- Rate-limit Node-бэкенда работает в памяти функции (достаточно для проекта; для высоких нагрузок потребуется KV-хранилище).
- **152-ФЗ:** PHP-вариант полностью размещается в РФ. Node-вариант исполняется на инфраструктуре выбранного хостинга — при строгом соответствии закону используйте PHP-хостинг в РФ или облачные функции в РФ; смена бэкенда делается одной строкой в `js/config.js`.
- Автотесты покрывают бэкенды (валидация, согласие, honeypot, rate-limit); клиентский UI (калькулятор, маска, адаптив) автоматизированных тестов не имеет.
- Браузерные проверки 320–1440 px и полный WCAG-аудит выполняются вручную при приёмке.
- Мессенджеры WhatsApp/Telegram отсутствуют в публичных контактах завода; они существуют только как опция связи в форме.

## 13. Если что-то не работает

| Симптом | Причина / решение |
|---------|--------------------|
| Форма отвечает 400 | Поле не прошло серверную валидацию: имя > 120 символов, телефон не 10–15 цифр, ник мессенджера не `[A-Za-z0-9_]{4,}`, неверный e-mail, не получено согласие на ПДн |
| Форма отвечает 429 | Превышен лимит заявок с IP (`rateLimitMax`=5 в 60 c). Подождать минуту; в PHP-режиме проверить `logs/ratelimit/` |
| Ответ без `ok` | Закрыть ловушку для ботов: скрытое поле `company` заполнило бот-расширение |
| Форма отвечает 404 | `API_URL` в `js/config.js` не совпадает с реальным обработчиком (`/send.php` или `/api/submit`); файл не загружен на хост |
| Демо: заявка «принята» с пометкой «демо» | Это ожидаемо — действует демо-режим (`IS_GITHUB_PAGES`): Pages не хранит заявки. Для реального приёмки формы — запуск на домене (раздел 9) |
| Заявка «принята», но письма нет | PHP: `mode` не `'real'`; письмо в «Спаме»; не настроены SPF/DKIM. Node: `NETLIFY_SUBMIT_MODE=test` → переключить в `real` |
| Письма попадают в «Спам» | Настроить SPF/DKIM/DMARC для домена отправителя |
| `/logs/mail.log` недоступен | Нормально — доступ запрещён `.htaccess`/nginx (`deny`) |
| `npm test` не запускается | `php` не в PATH — выполните `node tests/api.test.mjs` и `php tests/run_tests.php` явным путём |
| Шрифты не грузятся | Файлы `fonts/` не загружены на хост или путь нарушен; проверьте `GET /fonts/fonts.css` |
| Demo-ссылка в футере не видна | Она раскрывается только на `*.github.io` (скрипт `js/script.js`) — на других хостах скрыта намеренно |

## 14. Передача заказчику

Последовательность передачи после покупки решения:

1. Открыть доступ к репозиторию GitHub (или передать архив с git-историей).
2. Демо для показа: дать ссылку на GitHub Pages (раздел 3), пройти чек-лист вместе с заказчиком.
3. Боевой запуск: раздел 9 (домен, хостинг, конфигурация, проверка писем).
4. Оставить в `policy.html` реквизиты оператора (раздел 1 политики).
5. Передать `ACCEPTANCE_CHECKLIST.md` заказчику и зафиксировать подписи.

Чего в проекте нет: реальных адресов почты, паролей, токенов — все подобные значения задаются только локальными конфигами/переменными окружения, не попадающими в git.
